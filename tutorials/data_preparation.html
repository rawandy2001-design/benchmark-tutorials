Lee2019 data preparation and imputation tutorial¶

This public tutorial includes explanations, command examples and embedded figures. Commands use the companion analysis-code checkout as their working directory. Scientific inputs and native software environments are configured separately.

These examples use Lee2019 contacts and hg38 genome resources.

This tutorial follows the construction of raw and imputed inputs used by the analysis workflows. It shows the selection rule, cell-number subsets, raw pseudo-bulk aggregation and the two imputation branches. Commands are displayed as text: reading this notebook does not start a job or load contact files.

File excerpts below are read from the named local source files. Command settings use the corresponding Windows or WSL paths and configurable resources.

Use the shared path setup for the commands below:

source tutorials/paths.sh
cd "${BENCHMARK_ROOT}/code"

import os

BENCHMARK_ROOT = Path(os.environ["BENCHMARK_ROOT"])

1.2. Filter blacklisted contacts¶

The single-cell imputation implementation (data_preparation/single_cell_imputation/impute.py in the code repository) uses the same contact layout for filtering and prepare-impute:

hicluster filter-contact \
  --contact_table "$UNFILTERED_CONTACT_TABLE" \
  --chrom_size_path "${BENCHMARK_ROOT}/code/resources/genome/hg38.autosomal.chrom.sizes" \
  --blacklist_1d_path "$HG38_BLACKLIST" \
  --output_dir "$FILTERED_CONTACT_DIR" \
  --chr1 1 --pos1 2 --chr2 5 --pos2 6

Its build_filtered_contact_table block writes a new, headerless two-column contact_table_rmbkl.tsv. Each ID points to the generated <cell_id>.contact.rmbkl.tsv.gz, rather than its unfiltered source. Keep that filtered table with the metadata and the original table.

1.3. Select cell types and construct nested subsets¶

The downsampling implementation (data_preparation/downsampling/downsampling.py in the code repository) first joins metadata to contact paths by cell ID. It selects up to the two largest cell types with at least 100 cells. Ties are ordered by cell-type name.

For each selected type, the code sorts IDs, generates one permutation and uses successive prefixes. The settings and core selection are:

import numpy as np

MIN_CELLS = 100
CELL_STEP = 100
MAX_CELL_TYPES = 2

# group is the selected type's cell table, sorted by cell_id.
rng = np.random.default_rng()
group = group.iloc[rng.permutation(len(group))].reset_index(drop=True)
levels = list(range(MIN_CELLS, len(group) + 1, CELL_STEP))
if levels[-1] != len(group):
    levels.append(len(group))

subsets = {n: group.iloc[:n] for n in levels}

The ODC table above contains 1,245 cells. With 100-cell increments, the condition sizes are 100, 200, …, 1,200 and all 1,245 cells.

The notebook writes <condition>.cell_table.tsv for every subset and downsampling_manifest.csv with the original type, selected count, cell-table path and intended raw Cooler path.

2. Raw pseudo-bulk preparation¶

2.1. Merge each selected raw cell set¶

For a 10-kb downstream task, a subset is aggregated with:

hicluster merge-cell-raw \
  --cell_table "${BENCHMARK_ROOT}/data/lee2019/ODC_raw_10k_line/cell_table_100.txt" \
  --chrom_size_path "${BENCHMARK_ROOT}/code/resources/genome/hg38.autosomal.chrom.sizes" \
  --output_file "$MERGED_RAW_OUTPUT" \
  --chr1 1 --pos1 2 --chr2 5 --pos2 6 \
  --resolution 10000 --min_pos_dist 5000

Repeat for the saved conditions, including all. Select the resolution required by the downstream analysis. Keep each raw pseudo-bulk as the matched baseline for that cell set. Here, raw means non-imputed contact data after the specified filtering and aggregation.

2.2. Organize the Lee2019 pseudo-bulk inputs¶

The Lee2019 ODC example uses a 10-kb hg38 grid. Keep the cell-number label with each Raw and imputed matrix:

File Dataset and condition Role

Keep the selected cell IDs, cell-type label, cell number and resolution with each matrix. Match these identities between the Raw and imputed query maps, and use the all-cell Raw map as the common APA input.

3. Imputation workflows¶

3.1. Choose the imputation branch¶

Branch Starting input Output passed downstream
scHiCluster Filtered single-cell contacts Per-cell imputed Coolers and their cell table
Higashi Ordered native single-cell inputs and JSON configuration Native embeddings and chromosome-specific imputed HDF5 files
Pseudo-bulk methods A raw merged Cooler for a selected cell set An enhanced Cooler for that same set

Use saved subset IDs when matching raw and imputed conditions. A contact-file table, a Cooler table and a Higashi native input directory have different formats, even when they represent the same biological cells.

The examples below show how inputs are constructed. The downstream tutorials explain how each task consumes the relevant output.

3.2. Prepare and run scHiCluster imputation¶

The single-cell implementation (data_preparation/single_cell_imputation/impute.py in the code repository) prepares jobs from the filtered contact table. Its 100-kb command is:

hicluster prepare-impute \
  --cell_table "$FILTERED_CONTACT_TABLE" \
  --chrom_size_path "${BENCHMARK_ROOT}/code/resources/genome/hg38.autosomal.chrom.sizes" \
  --output_dir "$IMPUTE_OUTPUT_DIR" \
  --batch_size 1272 --pad 1 --cpu_per_job 48 \
  --chr1 1 --pos1 2 --chr2 5 --pos2 6 \
  --output_dist 500000000 --window_size 500000000 --step_size 500000000 \
  --resolution 100000

Then run the generated command script:

bash "${IMPUTE_OUTPUT_DIR}/snakemake_cmd.txt"

The imputation script is named snakemake_cmd.txt in this workflow. The native Loop preparation uses its separate snakemake_cmds.txt entry. The imputed Coolers and generated cell table supply downstream scHiCluster embedding or structural callers. Preserve their association with cell IDs.

3.3. Run Higashi preprocessing and imputation¶

Choose the matching JSON under single_cell_imputation/configs/, then configure data_dir, temp_dir, genome_reference_path, cytoband_path and the native input files. The repository provides Lee2019_higashi_100K.json, 500K.json and 1M.json. They retain resolution_cell=500000 and dimensions=128.

python data_preparation/single_cell_imputation/scripts/higashi_impute.py \
  --config "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells/native/Higashi/attempt01/config.json"

The runner calls the native stages in this order:

from higashi.Higashi_wrapper import Higashi

model = Higashi(str(BENCHMARK_ROOT / "data/higashi/embedding_all_autosomes_example_42cells/native/Higashi/attempt01/config.json"))
model.generate_chrom_start_end()
model.extract_table()
model.create_matrix()
model.prep_model()
model.train_for_embeddings()
model.train_for_imputation_nbr_0()
model.impute_no_nbr()
model.train_for_imputation_with_nbr()
model.impute_with_nbr()

Raw sparse matrices generated during preprocessing are used by native downstream routines such as Higashi masking. Imputed chromosome HDF5 arrays are separate outputs. The Domain/TAD tutorial identifies both kinds of input.

HiCNN2¶

Process human autosomes 1–22. For each chromosome, extract submatrices, run model 3 with ratio 16 and combine predictions. The chromosome-1 commands are:

python "${HICNN2_ROOT}/get_HiCNN2_input_fromCool.py" \
  "$RAW_100" 1 10000 ${HICNN2_WORK_DIR}/chr1.submats ${HICNN2_WORK_DIR}/chr1.index 22
python "${HICNN2_ROOT}/HiCNN2_predict.py" \
  -f1 ${HICNN2_WORK_DIR}/chr1.submats.npy -f2 ${HICNN2_WORK_DIR}/chr1.subMats_HiCNN23_16 \
  -mid 3 -m "$HICNN2_MODEL" -r 16
python "${HICNN2_ROOT}/combine_subMats.py" \
  ${HICNN2_WORK_DIR}/chr1.subMats_HiCNN23_16.npy ${HICNN2_WORK_DIR}/chr1.index.npy \
  1 10000 ${HICNN2_WORK_DIR}/predicted/chr1.predictedMat 22

After processing the 22 autosomes, merge the chromosome predictions:

python "${HICNN2_ROOT}/merge_chroms.py" ${HICNN2_WORK_DIR}/predicted/ ODC 100 \
  "$HICNN2_OUTPUT_COOL" \
  "$CHROM_SIZES" 10000
