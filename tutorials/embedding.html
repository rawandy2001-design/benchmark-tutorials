Embedding and cell-label evaluation tutorial¶

This public tutorial includes explanations, command examples and embedded figures. Command paths refer to the final_code3 analysis-code checkout. Scientific inputs and native software environments are configured separately.

This tutorial follows four native embedding workflows from shared cell inputs to cell vectors, predicted groups and ARI, AMI and V-measure. The worked example uses 42 Lee2019 cells, 14 original cell types, chr1–22 and 100-kb resolution. All commands are displayed as text; reading the notebook requires no kernel.

The original manuscript evaluates the assignments supplied by each workflow. The completed local example also demonstrates a separately recorded fixed K-means evaluation. Both routes are shown below, with their assignment sources kept explicit.

Use the shared path setup for the commands below:

source tutorials/paths.sh
export PATH="$(dirname "${EMBEDDING_PYTHON}"):${PATH}"
cd "${BENCHMARK_ROOT}/code"

from pathlib import Path
import os

BENCHMARK_ROOT = Path(os.environ["BENCHMARK_ROOT"])

1. Inputs and cell identities¶

1.1. Prepare the same biological cells¶

The example selects the first three cells of each type in the original metadata order. Every method receives the same 42 biological IDs.

Input Required format or contents Use
Raw five-column contacts Binned per-cell contact tables with five columns and no header Higashi, Fast-Higashi and scVI-3D
Imputed 100-kb Coolers One imputed Cooler (.cool) per cell at 100 kb scHiCluster
Imputed cell table Two columns linking each cell ID to its imputed Cooler file scHiCluster ID/path lookup
Reference labels Metadata with cell_id, cell_type and subtype, supplied with --metadata Original cell-type and subtype labels
Genome sizes hg38 autosomal chromosome names and lengths All 22 autosomes
Cytoband hg38 cytoband annotations Higashi input configuration

The raw contact columns are chrom1, pos1, chrom2, pos2, count, without a header. Positions are bp coordinates on the 100-kb grid. Prepared contacts retain the source values; labels are joined by biological cell ID.

The data inventory (embedding/DATA_REQUIREMENTS.md in the code repository) records the full input requirements.

1.2. Prepare ordered native inputs¶

Run the existing preparation script with the native Embedding environment. The commands below use the shared path prefix; the local data directory is D:/benchmark_higashi/embedding_all_autosomes_example_42cells/.

"${EMBEDDING_PYTHON}" embedding/tool/prepare_raw_embedding_example.py \
  --data-root "${BENCHMARK_ROOT}/data/higashi" \
  --metadata "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells/input/metadata.tsv" \
  --output-dir "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells" \
  --chromosomes autosomes --cells-per-type 3

Preparation writes the selected contacts, metadata.tsv, ordered filelist.txt, label_info.pickle, cell_summary.tsv, genome sizes, Higashi/Fast-Higashi configurations and preparation_manifest.json. The latter records IDs, source hashes, genomic scope and example parameters.

The four-method local runner can prepare and dispatch these stages together:

"${EMBEDDING_PYTHON}" embedding/tool/run_raw_embedding_examples.py \
  --data-root "${BENCHMARK_ROOT}/data/higashi" \
  --metadata "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells/input/metadata.tsv" \
  --chromosomes autosomes --cells-per-type 3 \
  --example-root "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells" \
  --impute-root "${BENCHMARK_ROOT}/data/higashi/impute"

The convenience runner uses the explicitly supplied raw-contact root and metadata. Both commands accept the saved metadata for the same selected cells. Environment and pinned-source locations are documented in software notes.

2. Embedding methods¶

2.1. Generate scHiCluster embeddings¶

The completed example uses the existing matched imputed Coolers. Its shared runner verifies their resolution and ordered cell table before invoking the native embedding command. The main native parameters are:

hicluster embedding \
  --cell_table_path "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells/native/scHiCluster/input/cell_table_100K.tsv" \
  --output_dir "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells/native/scHiCluster/attempt01/run1" \
  --dim 100 --dist 1000000 --resolution 100000 --scale_factor 100000 \
  --norm_sig --save_raw --cpu 48

For the prepared local example, dispatch this branch with:

"${EMBEDDING_PYTHON}" embedding/tool/run_raw_embedding_example.py --method scHiCluster \
  --example-root "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells" \
  --impute-root "${BENCHMARK_ROOT}/data/higashi/impute"

The example uses four CPUs and requests 100 dimensions. The native SVD returns 41 dimensions for these 42 cells. decomp/total_decomp.npz and the same-run embedding_cell_table.tsv establish the vector rows and cell IDs.

For contact-based use, tool/run_schicluster_embedding.py can prepare missing imputed matrices internally before embedding. The completed example already has those matrices and reuses them.

2.2. Generate Higashi embeddings¶

Higashi starts from the prepared raw contacts and the ordered native files. Its main configuration retains resolution=100000, resolution_cell=500000, dimensions=128 and neighbor_num=5. The small local example sets embedding_epoch=1 in its run-local configuration.

"${EMBEDDING_PYTHON}" embedding/tool/run_raw_embedding_example.py --method Higashi \
  --example-root "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells"

The runner calls tool/run_higashi_embedding.py, trains the embedding stage and exports the final cell checkpoint. Cell vectors come from the *_0_origin.npy output. The ordered filelist.txt and same-run label_info.pickle provide their biological IDs. Higher-index origin files contain genomic-bin embeddings and are not used as cell vectors here.

2.3. Generate Fast-Higashi embeddings¶

Fast-Higashi uses the same selected raw cells. Its preparation first constructs resolution-matched sparse inputs from their native ordered file list. The template retains resolution_fh=[100000], resolution_cell=100000, dimensions=128, bottle_neck=128 and restore_order=true. The local example separately sets native factorization rank 16 and final embedding dimension 8.

"${EMBEDDING_PYTHON}" embedding/tool/run_raw_embedding_example.py --method Fast-Higashi \
  --example-root "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells"

Its underlying embedding call has the following interface, after native preprocessing:

"${EMBEDDING_PYTHON}" embedding/tool/run_fast_higashi_embedding.py \
  --config "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells/native/Fast-Higashi/attempt01/config.json" \
  --output-dir "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells/native/Fast-Higashi/attempt01/run1" --rank 16 --final-dim 8

The exported matrix and accompanying ID/metadata tables use the same restored order. The model's cell-order mapping is retained in cell_order.tsv.

2.4. Generate scVI-3D embeddings¶

scVI-3D reads the prepared five-column raw contacts and cell summary. For all autosomes, the native command used by the wrapper is:

${EMBEDDING_PYTHON} ${SCVI3D_SCRIPT} -b 10 -c whole -r 100000 -n 130 -pool 2 -i "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells/input/contacts" -o "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells/native/scVI-3D/attempt01/run1" -cs "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells/input/cell_summary.tsv" -g "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells/input/hg38.autosomal.chrom.sizes" -gpu -p 1 -pca 5

Use the shared branch runner to retain its run records and standardized export:

"${EMBEDDING_PYTHON}" embedding/tool/run_raw_embedding_example.py --method scVI-3D \
  --example-root "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells"

The selected output is latentEmbeddings/scVI-3D_norm_PCA5.txt. Its native cell_info_summary_sorted.txt is checked against the original headered summary to recover the exact row-to-cell mapping.

3. Evaluation and resolutions¶

3.1. Export vectors with their cell identities¶

Every branch writes the following under result/<method>/:

cell_vectors.npy          native vectors, one row per cell
cell_ids.tsv              the corresponding ordered biological IDs
cell_metadata.tsv         original labels aligned to those IDs
embedding_manifest.json   dimensions, source files, commands and genomic scope
umap.tsv                  display coordinates

The completed example has these actual output shapes:

Method Cells Returned dimensions
scHiCluster 42 41
Higashi 42 128
Fast-Higashi 42 8
scVI-3D 42 5

The evaluators use cell IDs to align metadata and predictions. UMAP provides display coordinates; it does not determine these native vectors or groups.

3.2. Evaluate the original workflow assignments¶

For the manuscript route, supply the groups produced by the selected original workflow as a headered table. The table columns are cell_id and cluster_assignment.

Use the shared evaluator after exporting same-run vectors, IDs and metadata:

"${EMBEDDING_PYTHON}" embedding/tool/evaluation/run_evaluation.py evaluate-embedding \
  --vectors "$VECTORS" --cell-ids "$CELL_IDS" --metadata "$CELL_METADATA" \
  --cluster-assignments "$ORIGINAL_ASSIGNMENTS" \
  --assignment-source "$ASSIGNMENT_SOURCE" \
  --assignment-origin original_workflow --label-column cell_type \
  --output-dir "$EVALUATION_OUTPUT_DIR"

Reference labels come from the original metainfo. Predicted groups come from the workflow output. For a subtype evaluation, provide the corresponding subset/assignments and select its metadata column.

The configurable evaluation notebook (embedding/tool/evaluation/embedding_evaluation.py in this folder) contains native export adapters and selectors for existing original outputs.

3.3. Run the completed fixed-group example¶

The separate local example demonstrates the entire scoring chain using newly computed groups. Each method is clustered directly on its native vectors with the same prespecified settings:

from sklearn.cluster import KMeans

predicted = KMeans(
    n_clusters=14,
    random_state=0,
    n_init=20,
    max_iter=300,
    tol=0.0001,
    algorithm="lloyd",
).fit_predict(vectors)

The fit receives vectors only. The 14-cluster count is set for this known 14-type example; per-cell reference labels enter during scoring. Predictions are saved as predicted_groups.tsv before the evaluator is called with --assignment-origin new_example.

"${EMBEDDING_PYTHON}" embedding/tool/run_embedding_metrics_example.py \
  --example-root "${BENCHMARK_ROOT}/data/higashi/embedding_all_autosomes_example_42cells" \
  --n-clusters 14 --seed 0 --n-init 20

Use the evaluation environment for this command. Completed runs with the same inputs and settings reuse the saved groups. The original manuscript's assignments remain a separate input route.

3.4. Read ARI, AMI and V-measure¶

The implementation uses scikit-learn's adjusted Rand index, adjusted mutual information and V-measure (beta=1). Cluster identifiers need no manual matching to cell-type names. The three scores are reported separately; negative adjusted scores are retained.

The existing 42-cell example produced the following saved values, rounded for display. They are demonstration results, separate from the manuscript figures.

Method ARI AMI V-measure
scHiCluster -0.0088 -0.0258 0.4179
Higashi 0.1798 0.2323 0.6662
Fast-Higashi 0.3852 0.4648 0.7771
scVI-3D 0.0798 0.1145 0.5826

The figure and table are retained from the completed run; opening this tutorial does not recalculate them. The full-precision CSV and manifests remain under result/clustering/kmeans_k14_seed0_ninit20/ in the example root.

3.5. Evaluate other resolutions¶

Existing original-workflow outputs can be evaluated at 100 kb, 500 kb and 1 Mb with the same export and scoring sequence. Select the resolution-matched contacts/configuration, original row-identity files and assignments, then use a separate output directory for every method, dataset, resolution and label task.

# Select these in tool/evaluation/embedding_evaluation.py.
METHOD = "Fast-Higashi"
CONTACT_RESOLUTION = 500_000  # 100_000, 500_000 or 1_000_000
DATASET_CONFIG_NAME = "Lee2019"
TASK = "cell_type"
LABEL_COLUMN = "cell_type"

The configuration guide (Higashi configuration) lists the 100K, 500K and 1M templates. Their internal model settings remain as documented; the contact resolution and condition-specific input/output paths select the condition. Changing a selector does not rebin an existing 100-kb matrix or train a model.

The completed four-method convenience runner above constructs the 100-kb example. Its --chromosomes switch changes chromosome scope, not resolution.
